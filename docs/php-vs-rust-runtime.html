Aurelin · runtime mental model

What changes when requests run concurrently?

Laravel capabilities are the things developers need. PHP’s common deployment model influences how Laravel delivers them. Rust changes some of that machinery—but it does not make durability, security, or slow work disappear.

Important distinction: “PHP usually handles a request in a worker” describes the common PHP-FPM model, not an absolute PHP limitation. Laravel Octane can also run long-lived workers.

What Aurelin can simplify or rethink

Initialize once

Load and validate configuration, build routes, and create connection pools when the server starts—not for every request. This is an opportunity, not a PHP requirement.

Pass state explicitly

Rust types can make handler dependencies visible. A large runtime container or reflection-driven discovery may be unnecessary if explicit state and registration stay ergonomic.

Keep quick I/O inline

Async work that belongs to the response can run without occupying a whole worker thread. Still apply timeouts and resource limits where needed.

Use pools, not per-request clients

Long-lived database and HTTP clients reuse connections. Pool limits and transaction boundaries still matter under concurrency.

Bound expensive work

Password hashing and other CPU-heavy tasks can consume executor resources. Run them off the async path and limit parallelism.

Keep request state isolated

A long-lived process serves many users. Don’t let one request’s mutable data leak into another; use request-scoped state and safe shared-state patterns.

Queue or inline? Decide by guarantees, not language

Inline async work

Use when the result is part of the response, the work is bounded, and it’s acceptable for the request to fail if the operation fails.

→

Durable database queue

Use when work must survive a process restart, retry later, run on a schedule, or complete independently of the response. Redis is not inherently required.

Async task ≠ durable job. A spawned in-memory task can be lost if the process stops. A queue persists work so a worker can pick it up later.

Rust concurrency does not replace these capabilities

Authentication & authorization

Concurrency doesn’t decide who a user is or what they may do.

Validation & CSRF protection

More requests at once do not make untrusted input safe.

Transactions & durable work

Async I/O does not make a multi-step update atomic or survive a crash.

Takeaway: preserve Laravel’s user-facing behavior; don’t copy runtime-specific machinery without a reason. Async only helps when the libraries used are actually async—blocking code can still stall executor threads.
